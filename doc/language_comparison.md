# 各言語の実装比較と推奨環境

\hyper_copy\ は、単一の要件に対して **Ruby, Go, Rust, C#** の 4 つの言語で実装されています。このドキュメントでは、各言語で CLI ツールを実装した場合の特徴、メリット・デメリット、およびパフォーマンスを比較し、最終的にどのバージョンを使用すべきかの結論をまとめます。

## ベンチマーク比較

10個の巨大なファイルに対してコピーと文字列置換を実行した結果です。

| Language | Execution Time (s) | Binary Size |
| --- | --- | --- |
| Rust | 1.669 s | 1.80 MB |
| Go | 2.321 s | 3.00 MB |
| C# (Standard) | 2.590 s | 144.00 KB |
| Ruby | 3.353 s | N/A (Script) |
| C# (Self-Contained) | 4.679 s | 67.65 MB |

## 各言語の特徴とメリット・デメリット

### 1. Rust
- **メリット**: 
  - 圧倒的な実行速度（最速）。
  - ランタイム不要で、単一のコンパクトなバイナリ（1.8MB）として配布可能。
  - メモリ安全性と型安全性が非常に高く、実行時のエラーが起きにくい。
- **デメリット**: 
  - 学習コストが高く、文字列のライフタイムや所有権の管理がやや煩雑。
  - コンパイルに時間がかかる。

### 2. Go
- **メリット**: 
  - 実行速度が非常に速く、Rustに次ぐパフォーマンス。
  - 依存関係のない単一バイナリを簡単にクロスコンパイル（Windows, Mac, Linux向け）できる。
  - 文字列処理や標準ライブラリが直感的で、コードがシンプルに保ちやすい。
- **デメリット**: 
  - バイナリサイズがRustよりやや大きくなる（3.0MB。ただしCLIツールとしては十分許容範囲）。

### 3. C# (.NET 9)
- **メリット**: 
  - Windows環境やエンタープライズでの親和性が高い。
  - フレームワーク依存版 (Standard) であれば、バイナリサイズが驚異的に小さい (144KB)。
- **デメリット**: 
  - Standard版を実行するには、ターゲットマシンに .NET ランタイムがインストールされている必要がある。
  - ランタイムを同梱した自己完結型 (Self-Contained) でビルドすると、バイナリサイズが巨大化 (約67MB) し、起動時のオーバーヘッドで実行速度も遅くなる。

### 4. Ruby
- **メリット**: 
  - 開発スピードが最速。正規表現や文字列操作の記述が極めて柔軟で直感的。
  - コンパイル不要で、スクリプトを直接編集してすぐ動かせるためプロトタイピングに最適。
- **デメリット**: 
  - 実行にはRubyの実行環境が必要となるため、配布のハードルが高い（特にWindows）。
  - スクリプト言語の特性上、実行速度はコンパイル言語と比較すると劣る。

## 結論（おすすめのバージョン）

用途と環境に応じて、以下の使い分けを推奨します。

🏆 **総合的なおすすめ: Go 版 または Rust 版**
事前準備なしに単一の実行ファイルをポンと置くだけで動き、高速に動作するため、他人に配布したり様々な環境で使う CLI ツールとしては **Go版** または **Rust版** がベストな選択です。
特にクロスコンパイルの手軽さを重視するなら Go、極限のパフォーマンスとバイナリサイズの小ささを求めるなら Rust を選ぶと良いでしょう。

💻 **Windows / .NET 開発者向け: C# 版 (Standard)**
既に社内や自身のPCに .NET ランタイムがインストールされていることが確実な環境であれば、144KBという極小サイズの C# 版（Standard）が非常に魅力的です。

🛠️ **カスタマイズ・開発用: Ruby 版**
仕様を頻繁に変更したり、自分専用のロジックを手軽に書き換えながら使いたい場合は、コンパイル不要でサクッと修正できる Ruby 版が最も扱いやすいです。プロジェクトのプロトタイプとしても機能しています。
