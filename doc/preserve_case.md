# Preserve Case の仕組み (VS Code 準拠)

\hyper_copy\ では、Visual Studio Code と同様のロジックを用いて文字列置換時の大文字・小文字（ケース）をスマートに維持しています。このドキュメントでは、内部的にどのようなルールで変換が行われているかを解説します。

## 適用される 5 つのルール

置換処理は、以下のルールを上から順に評価して適用します。

### 1. ハイフン (\-\) やアンダースコア (\_\) による分割処理 (ケバブ/スネークケース対応)

マッチした文字列と置換先文字列の **両方** にハイフン（またはアンダースコア）が含まれる場合、その文字で分割し、各パーツに対して再帰的に Preserve Case を適用してから再結合します。

- **例**: \oo-bar\ -> \az-qux\ の置換
  - 元テキストが \FOO-BAR\ の場合 -> \BAZ-QUX\ に変換
  - 元テキストが \Foo_Bar\ の場合（ルールに合致しないので分割されず、そのままのケース判定に進みます）

### 2. すべて大文字 (\ALL CAPS\)

マッチした文字列が「すべて大文字」の場合、置換先も **すべて大文字** に変換します。

- **条件**: \match.toUpperCase() == match\`n- **例**: \FOO\ にマッチ ＋ 置換先 \BarBaz\ -> **\BARBAZ\**

### 3. すべて小文字 (\ll lowercase\)

マッチした文字列が「すべて小文字」の場合、置換先も **すべて小文字** に変換します。

- **条件**: \match.toLowerCase() == match\`n- **例**: \oo\ にマッチ ＋ 置換先 \BarBaz\ -> **\arbaz\**

### 4. 先頭のみ大文字 (\PascalCase\ / \TitleCase\)

マッチした文字列の1文字目が大文字の場合、置換先の **1文字目を大文字にし、2文字目以降はそのまま（置換先の状態を維持）** にします。

- **条件**: \match[0]\ が大文字
- **例**: \Foo\ にマッチ ＋ 置換先 \BarBaz\ -> **\BarBaz\**
  - ※ \FooBar\ -> \AaaBbb\ のように、置換先の内部キャメルケース（途中の大文字）は破壊されずに保持されます。

### 5. 先頭のみ小文字 (\camelCase\)

上記のどれにも当てはまらず、マッチした文字列の1文字目が小文字の場合、置換先の **1文字目を小文字にし、2文字目以降はそのまま** にします。

- **条件**: \match[0]\ が小文字（実質的に \ooBar\ のようなキャメルケース用）
- **例**: \ooBar\ にマッチ ＋ 置換先 \AaaBbb\ -> **\aaBbb\**

---

## 内部実装のポイント

このロジックを実装する上で非常に重要なのが、**ルール4における「2文字目以降の扱い」** です。

単なるプログラミング言語の組み込み関数（Rubyの \.capitalize\ など）を使うと、「1文字目を大文字にし、**2文字目以降をすべて小文字にする**」という挙動になりがちです。これにより、ユーザーが意図して指定した置換文字列（\BarBaz\）の途中の大文字が破壊され、\Barbaz\ となってしまうバグが発生します。

\hyper_copy\ では VS Code と同様に、ケース判定を自前で実装し「2文字目以降はユーザーが指定した置換先文字列のケースをそのまま信用して維持する」ことで、直感的で期待通りの Preserve Case を実現しています。
