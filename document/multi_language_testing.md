# マルチ言語実装の開発・テスト手法

`hyper_copy` は、単一の要件（ファイルコピーとケースを維持した文字列置換）を **Ruby, Go, Rust, C#** の 4 つの言語で実装しています。このドキュメントでは、複数の言語で全く同じ挙動をするツールを開発し、品質を担保するための手法について解説します。

## 1. 開発フロー（プロトタイプ駆動）

複数言語でツールを作る場合、最初から全ての言語で同時に開発を進めるのではなく、**スクリプト言語によるプロトタイプ駆動** を採用しています。

1. **Rubyでの仕様策定と実装**: 
   まずは最も文字列操作が得意で、コンパイルが不要な Ruby を使ってロジックを実装します。ここで正規表現のパースや、大文字・小文字の維持（Preserve Case）の複雑な条件分岐の正解を作ります。
2. **他言語への移植**: 
   Ruby で完成したロジックを、Go, Rust, C# に移植します。どの言語でも処理のフロー（コマンドライン引数の解析 -> ファイルリストアップ -> 競合チェック -> 文字列置換 -> ファイル書き込み）が同じになるように設計しています。

## 2. 統合テスト戦略（Single Test Suite）

各言語ごとにユニットテストを書くのではなく、**単一の Ruby スクリプト (	est/test_hyper_copy.rb) を使って全言語のバイナリをブラックボックステスト** する手法を採用しています。

### テストの仕組み
- Ruby の `Minitest` を使用し、一時ディレクトリ (`Dir.mktmpdir`) の中で実際のファイルを生成します。
- コマンドラインから各言語の実行コマンド（`
uby hyper_copy.rb`, `go run main.go`, `cargo run`, `dotnet run`）をシステムコールとして呼び出します。
- コマンド実行後の「ファイルが生成されたか」「中身の文字列が期待通り置換されているか」「エラー時のメッセージが正しいか」をアサートします。

### この手法のメリット
1. **挙動の完全一致の保証**: 
   「同じ入力ファイル・同じ引数を与えれば、必ず同じ結果のファイルが出力される」という CLI ツールとしてのインターフェース仕様を、全言語で完全に揃えることができます。
2. **テストコードの保守性**: 
   テストケースを追加する際、Ruby のスクリプトに1つテストを追加するだけで、自動的に4つの言語すべてのテストが実行されます。
3. **リファクタリングの安心感**: 
   ある言語の内部ロジックをリファクタリングしたり、VS Code 互換の Preserve Case ロジックのような複雑な要件を追加した際にも、全言語でテストを回すことでデグレを防ぎ、同期漏れを検出できます。

## 3. CI/CD (GitHub Actions) との連携

このマルチ言語テストは GitHub Actions 上でも容易に実行できます。
リポジトリにコミットが Push された際、CI 上で Ruby, Go, Rust, C# の環境をセットアップし、`
uby test/test_hyper_copy.rb` を一発実行するだけで、全言語の実装が仕様を満たしているかを横断的にチェック可能です。

---

総括すると、**「Ruby で仕様を作り込み、Ruby で横断的にテストし、各コンパイル言語で最速のバイナリを出力する」** というのが、`hyper_copy` におけるマルチ言語開発のベストプラクティスとなっています。
